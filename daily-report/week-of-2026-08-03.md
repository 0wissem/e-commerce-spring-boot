## Monday 2026-08-03 — System-design close-out + high-contention patterns

### What I did

- **Worked through a flash-sale design** (limited stock, ~1M concurrent buyers) and mapped it to patterns already in our stack. Core failure = overselling via a race on the stock counter; the correct fix is an atomic in-memory decrement (Redis) fronting the DB so the flood never reaches Postgres, with winners deduplicated by an idempotency key and drained through a queue.
- **Reviewed our existing concurrency handling** against this: confirmed where we rely on transactional boundaries vs where a hot-path counter would need to move out of the DB, and noted the trade-offs (optimistic locking → retry storm under contention; single-row pessimistic lock → serialization bottleneck).

### Key takeaways

- Under extreme contention, absorb load in an atomic counter; keep the DB for the ~100 real writes.
- Optimistic vs pessimistic locking is a contention-level decision, not a default.

## Tuesday 2026-08-04 — Review pass: OOP boundaries + Spring wiring

### What I did

- **Audited the dependency-injection wiring** across the services. Confirmed all services use constructor injection with `final` fields (no field injection), which is why the unit tests can run without a Spring context. Verified the `@Service`/`@Repository`/`@Component` vs `@Bean` split is correct (own classes annotated; third-party objects like the cache manager provided via `@Bean` factory methods).
- **Traced the `IOrderRepository` port/adapter boundary** and re-verified the hexagonal layering (domain → application → infrastructure). **Finding:** the domain-layer port imports Spring Data's `Page`/`Pageable`, a small leak of framework types into the pure layer — logged as a low-priority cleanup (introduce a domain-owned paging type or accept the pragmatic trade-off).

### Key takeaways

- Constructor injection is what keeps the service layer unit-testable — confirmed consistent across services.
- Minor architectural leak identified in the repository port (Spring types in the domain), logged for follow-up.
